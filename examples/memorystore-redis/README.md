# Memorystore for Redis example

This isolated root composes the repository's VPC/Private Service Access foundation with the secure Memorystore for Redis module.

It demonstrates:

- a custom-mode VPC and workload subnet;
- an explicit Private Service Access allocation and Service Networking connection;
- a `STANDARD_HA` Redis 7.2 instance;
- Redis AUTH enabled;
- TLS in-transit encryption enabled;
- provider-level deletion prevention;
- an explicit module dependency so Memorystore is created only after Private Service Access exists.

## Prerequisites

The target project must have these APIs enabled before apply:

- `compute.googleapis.com`;
- `servicenetworking.googleapis.com`;
- `redis.googleapis.com`.

The deployment identity needs permissions to manage the VPC/Private Service Access resources and the Memorystore instance.

## Validate without creating infrastructure

```bash
terraform init -backend=false -input=false -lockfile=readonly
terraform validate
terraform plan -input=false -var='project_id=my-project'
```

The example intentionally has no backend because it is not a production environment root.

## Address plan

The example uses:

```text
Workload subnet:        10.20.0.0/24
Private Service Access: 10.30.0.0/16
```

Memorystore uses `PRIVATE_SERVICE_ACCESS` and consumes an available service range from that allocation. Real environments must coordinate these ranges with existing VPCs, peering, VPN/Interconnect routes, and on-premises networks.

## AUTH and TLS

The Redis AUTH string is generated by Memorystore. Terraform provider state may contain that computed sensitive value, so the remote state must be treated as sensitive even though this example does not expose the value as an output.

The example also enables TLS. Clients must support TLS 1.2 or later and trust the Memorystore server CA. AUTH retrieval, CA distribution, and application client configuration remain explicit operational steps outside this Terraform example.

## Cloud Run composition

`module.network.direct_vpc` can be passed to a Cloud Run service or job so the workload reaches the private Redis endpoint without a Serverless VPC Access connector:

```hcl
direct_vpc = module.network.direct_vpc
```

Keep `PRIVATE_RANGES_ONLY` unless the workload intentionally needs all outbound traffic routed through the VPC.

## Lifecycle warning

Both the Service Networking connection and Redis instance use destructive-operation prevention by default. Applying this example creates real, billable Google Cloud resources. Agents and CI must not run `terraform apply` or `terraform destroy` unless explicitly authorized.
